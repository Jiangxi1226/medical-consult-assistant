## 📖 项目简介

一个面向**医疗咨评估**场景的多智能体会诊系统。患者描述症状后，系统**并行**调度多个专科智能体（心内科、呼吸科、消化科、神经科等）各自评估，再由**仲裁智能体**汇总结论。整个链路强制**分层严格 JSON 输出**，回答结构化、可解析、可复现。

> **为什么做**：单模型"一股脑"回答容易漏诊、且不可信。本项目把"多专科并行会诊 + 仲裁汇诊"的医生工作流搬到 AI 侧，并用**红旗强制就医、用药禁忌校验**作为安全底线——**宁可过度提示就医，绝不漏报急重症**。

**三条设计底线**
1. **红旗规则层兜底**：疑似急重症红旗命中即强制就医，**不依赖 LLM**，杜绝漏报;
2. **分层严格 JSON**：结构校验 + 业务校验两层把关，字段残缺**绝不悄悄回退为空对象**;
3. **请求隔离 + 安全边界**：多会话互不串扰，输入扫描防注入，限流防刷接口。

## ✨ 核心特性

### 🤖 多科并行会诊
- `LangGraph` 驱动，多个专科智能体**并行评估**，互不阻塞、高效汇诊
- **仲裁智能体**收集各科结论、去重消歧、产出最终建议与就医分流（分级）

### 🛡️ 红旗拦截（规则层优先）
| 机制 | 说明 |
|------|------|
| **红旗症状库** | 覆盖心/脑/呼吸等急重症，含**患者口语化表述**（如"喘不上气""心口堵") |
| **规则层匹配** | 命中即强制指引及时就医，**不依赖 LLM 判断**，杜绝漏报 |
| **关键词拆分** | 处理含死词的长词，避免正则误匹配 |

### 💊 用药禁忌校验
- **药物联用禁忌**、过敏史、特殊人群（孕 / 幼 / 肝肾功能）限制
- 联用风险 ≠ 急诊红旗：红色 / 黄色分级清晰，命中即给出明确结论

### 📐 分层严格 JSON
- 按「结构校验 → 业务校验」两层把关，字段残缺 / 不合法则**拒绝落盘**，绝不悄悄回退为空对象
- 请求隔离，多会话互不串扰

### 🛡️ 安全边界
- **输入校验**：类型 / 长度校验，超长或非字符串请求直接 `400`
- **Prompt 注入防护**：输入扫描 + 高危指令隔离（`〔标记为数据〕`）
- **限流保护**：内存级速率限制，防恶意刷接口

### 🔐 LLM 配置灵活（非绑定某一家）
- 支持任意 **OpenAI 兼容端点**，`base_url + api_key + 模型名` 可随时更改、热更新，无需重启
- 右上角「⚙ API配置」弹窗填写；未配置时明确提示，不假装可用

## 🏗️ 系统架构

```
患者主诉
   │
   ▼
[入口]  /api/v1/consult/stream · 输入校验 + 注入扫描 + 红旗规则预检
   │
   ├─ 命中红旗 ──→ 直接强制就医结果（规则层，不依赖 LLM）
   │
   ▼
[并行会诊]  心内科 → 呼吸科 → 消化科 → 神经科 → ...  (LangGraph 并行)
   │
   ▼
[仲裁智能体]  汇总各科 → 去重消歧 → 分级建议 → 就医分流
   │
   ▼
[严格JSON]  分层结构校验 + 业务校验 → 只落合法结果
   │
   ▼
[SSE 流式]  分阶段推送（生成中 → 结论）· 审计留痕
```

## 🔄 核心机制走读

### 1. 红旗强制就医（规则层兜底）
症状先经过**红旗规则预检**——命中急重症关键词（含患者口语词），由确定性规则直接产出"请及时就医"结论，**完全绕过 LLM**。这是防漏报的第一道、也是最可靠的闸门。

### 2. 分层严格 JSON（防"假成功"）
```
[模型输出]
   │ GATE1: 结构校验（必填字段/类型/枚举）
   │   └─ 不合法 → 拒绝，不落盘
   ▼
[GATE2 业务校验]（值域/交叉约束）
   └─ 不合法 → 拒绝
   ▼
[ACCEPT]  → 落盘为合法结果
```
业务校验失败**不重试、绝不悄悄 `{}`**——宁可让用户重发，也不产出残缺结果。

### 3. 并行会诊 + 仲裁
各专科智能体独立评估（并行、互不等待），仲裁智能体汇总时：去重、消歧、按严重度分级、给出就医分流建议。全流程经 `stream_flow` 记录 `_audit`（红旗、候选、各科结论、交互、是否降级）。

### 4. 用药禁忌交叉校验
对处方中的**联用组合**逐对校验禁忌库；对过敏史 / 特殊人群命中即升为明确风险提示。限制校验分级：红（禁用）/ 黄（谨慎），绝不与"急诊红旗"混淆。

## 🚀 快速开始

### 环境要求
- Python 3.11+
- 任意 OpenAI 兼容的 LLM API

### 安装

```bash
# 1. 克隆仓库
git clone https://github.com/Jiangxi1226/medical-consult-assistant.git
cd medical_assistant

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置 LLM（两种方式任选）
cp .env.example .env            # 或直接在界面右上角「⚙ API配置」填写
```

> `base_url` 必填且须为 `https`；`api_key` / 模型名必填。三者均可随时更改，**热更新，无需重启**。

### 启动

```bash
python app.py
```

打开浏览器访问：[http://localhost:8001](http://localhost:8001)

## 🛡️ 安全设计

- **密钥不入库**：`LLM_API_KEY` 仅存于项目根 `.env`（已被 `.gitignore` 忽略）
- **输入校验前置**：超长 / 非字符串请求直接 `400`，进入会诊前先扫描注入
- **高危指令隔离**：命中即替换为 `〔标记为数据〕`，分界符号隔离系统指令与用户输入
- **限流保护**：内存级速率限制，防恶意刷接口
- **审计留痕**：每次会诊记录红旗 / 各科结论 / 是否降级，全程可追溯

> ⚠️ **免责声明**：本项目仅供就医参考，任何结论与建议**不能替代专业医疗诊断**。含红旗症状请务必及时就医。
