## 📖 项目简介

一个面向**医疗咨评估**场景的多智能体会诊系统。患者描述症状后，系统**并行**调度四个专科智能体（**内科 / 外科·骨科 / 药剂 / 风险**）各自评估，再由**仲裁智能体**汇总结论。整个链路强制**分层严格 JSON 输出**，回答结构化、可解析、可复现。

> **为什么做**：单模型"一股脑"回答容易漏诊、且不可信。本项目把"多专科并行会诊 + 仲裁汇诊"的医生工作流搬到 AI 侧，并用**红旗强制就医、用药禁忌校验**作为安全底线——**宁可过度提示就医，绝不漏报急重症**。

**三条设计底线**
1. **红旗规则层兜底**：疑似急重症红旗命中即强制就医，**不依赖 LLM**，杜绝漏报;
2. **分层严格 JSON**：结构校验 + 业务校验两层把关，字段残缺**绝不悄悄回退为空对象**;
3. **请求隔离 + 安全边界**：多会话互不串扰，输入扫描防注入，限流防刷接口。

## ✨ 核心特性

### 🤖 分层会诊编排（对齐真实 MDT 结构）
- **临床科室是「变量」**：由分诊结果 / 知识库症状命中决定本次启动哪几路（内科、外科·骨科），分诊**真正参与路由**而非摆设
- **药剂审方、红旗预警是「常量」**：任何病例都要过的流程安全关卡，不参与路由、不会被跳过
- **规则层优先于 LLM**：命中红旗 → 强制全科室（急重症不省路，也不交给 LLM 决定）；知识库症状命中优先于 LLM 分诊文本
- **仲裁智能体**收集各科结论、去重消歧、产出最终建议与就医分流；**未被启用的科室会显式告知仲裁**，不会被误读为"该科无意见"
- **两条链路各司其职**：`stream_flow`（线程池并行）服务**实时 SSE 打字机**；`consultant_graph`（LangGraph 状态图：分诊 → 路由 → 并行会诊 → 仲裁）服务**回归评估与全链路审计**

### 🛡️ 红旗拦截（规则层优先）
| 机制 | 说明 |
|------|------|
| **红旗症状库** | 覆盖心/脑/呼吸等急重症，含**患者口语化表述**（如"喘不上气""心口堵") |
| **规则层匹配** | 命中即强制指引及时就医，**不依赖 LLM 判断**，杜绝漏报 |
| **关键词拆分** | 处理含死词的长词，避免正则误匹配 |

### 💊 用药禁忌校验
- **药物联用禁忌**、过敏史、特殊人群（孕 / 幼 / 肝肾功能）限制
- 联用风险 ≠ 急诊红旗：红色 / 黄色分级清晰，命中即给出明确结论

### 📐 分层严格 JSON
- 按「结构校验 → 业务校验」两层把关，字段残缺 / 不合法则**拒绝落盘**，绝不悄悄回退为空对象
- 请求隔离，多会话互不串扰

### 🛡️ 安全边界
- **输入校验**：类型 / 长度校验，超长或非字符串请求直接 `400`
- **Prompt 注入防护**：输入扫描 + 高危指令隔离（`〔标记为数据〕`）
- **限流保护**：内存级速率限制，防恶意刷接口

### 🔐 LLM 配置灵活（非绑定某一家）
- 支持任意 **OpenAI 兼容端点**，`base_url + api_key + 模型名` 可随时更改、热更新，无需重启
- 右上角「⚙ API配置」弹窗填写；未配置时明确提示，不假装可用

## 🏗️ 系统架构

```
患者主诉
   │
   ▼
[入口]  /api/v1/consult/stream · 输入校验 + 注入扫描 + 红旗规则预检
   │
   ├─ 命中红旗 ──→ 直接强制就医结果（规则层，不依赖 LLM）
   │
   ▼
[科室路由]  临床科室动态选路：内科 / 外科·骨科（按分诊结果或知识库命中）
   │        （红旗命中则强制全科室；指向不明确则保守全跑，宁可多算不漏诊）
   │
   ▼
[并行会诊]  选中的临床科室 + 常驻横切关卡（药剂审方 · 红旗预警）   并行，互不等待
   │
   ▼
[仲裁智能体]  汇总各科 → 去重消歧 → 分级建议 → 就医分流
   │           （未启用/失败的科室显式标注，不臆造其结论）
   │
   ▼
[严格JSON]  分层结构校验 + 业务校验 → 只落合法结果
   │
   ▼
[SSE 流式]  分阶段推送（生成中 → 结论）· 审计留痕 · 客户端断开即止损
```

## 🔄 核心机制走读

### 1. 红旗强制就医（规则层兜底）
症状先经过**红旗规则预检**——命中急重症关键词（含患者口语词），由确定性规则直接产出"请及时就医"结论，**完全绕过 LLM**。这是防漏报的第一道、也是最可靠的闸门。

### 2. 分层严格 JSON（防"假成功"）
```
[模型输出]
   │ GATE1: 结构校验（必填字段/类型/枚举）
   │   └─ 不合法 → 拒绝，不落盘
   ▼
[GATE2 业务校验]（值域/交叉约束）
   └─ 不合法 → 拒绝
   ▼
[ACCEPT]  → 落盘为合法结果
```
业务校验失败**不重试、绝不悄悄 `{}`**——宁可让用户重发，也不产出残缺结果。

### 3. 科室路由 + 并行会诊 + 仲裁

**为什么需要路由**：分诊的本职是"把不相关的科室筛掉"。若四路无条件全跑，分诊就只是给仲裁多添一段上下文、并不影响任何路径决策——那是装饰而非机制。因此会诊方按性质分两层：

| 层 | 成员 | 性质 |
|----|------|------|
| **临床科室** | 内科、外科·骨科 | **变量**：按病情选路，1~2 路 |
| **流程关卡** | 药剂审方、红旗预警 | **常量**：每个病例都要过，不参与路由 |

**路由判定顺序**（安全优先于省调用，实现在 `utils/dept_router.py`）：

```
1) 规则层命中红旗        → 全科室   （急重症不省路，且不由 LLM 决定）
2) 知识库症状命中（确定性）→ 只跑命中的科室
3) LLM 分诊的科室倾向文本 → 关键词映射
4) 指向不明确            → 全科室   （宁可多算一路，不漏诊）
```

仅"判为简单主诉且无任何科室指向"时才真的不启动专科会诊。各专科智能体独立评估（并行、互不等待），仲裁智能体汇总时：去重、消歧、按严重度分级、给出就医分流建议。

**两个易被忽略的细节**：
- 未被路由选中的科室会**显式标注 `skipped`** 并写进给仲裁的简报。否则仲裁看到"没有内科这一行"，会把它误读成"内科没意见"，进而臆造结论。
- 会诊**失败**（`degraded`）与**未启用**（`skipped`）是两种不同状态，都不得与"该科意见为空"混同。

全流程记录 `_audit`（路由决策与依据、红旗、候选、各科结论、交互、是否降级）。

> **两条链路并存，各司其职**：
> - **实时 SSE 链路** `graph/stream_flow.py`：`ThreadPoolExecutor` 并行跑选中的各科，边生成边逐 token 推送（打字机体验）；路由全由**规则层**决定（知识库症状命中），不引入 LLM 分诊节点以保实时性；
> - **结构化全会诊图** `graph/consultant_graph.py`：用 `LangGraph` 编排「分诊 → 路由 → 并行会诊 → 仲裁」，产出完整 `state`，服务**离线评估与审计复盘**（`eval/run_eval.py` 调用）。

### 4. 用药禁忌交叉校验
对处方中的**联用组合**逐对校验禁忌库；对过敏史 / 特殊人群命中即升为明确风险提示。限制校验分级：红（禁用）/ 黄（谨慎），绝不与"急诊红旗"混淆。

## 📦 技术栈

| 层 | 技术 |
|----|------|
| 后端 | Python 3.11+ · FastAPI · Uvicorn |
| 编排 | LangGraph（结构化会诊图）+ ThreadPoolExecutor（实时流式四路并行） |

| 审计 | JSONL 审计日志（.gitignore 忽略） |

## 🚀 快速开始

### 环境要求
- Python 3.11+
- 任意 OpenAI 兼容的 LLM API

### 安装

```bash
# 1. 克隆仓库
git clone https://github.com/Jiangxi1226/medical-consult-assistant.git
cd medical_assistant

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置 LLM（两种方式任选）
cp .env.example .env            # 或直接在界面右上角「⚙ API配置」填写
```

> `base_url` 必填且须为 `https`；`api_key` / 模型名必填。三者均可随时更改，**热更新，无需重启**。

### 启动

```bash
# 方式一：本地启动
python app.py

# 方式二：Docker
docker compose up -d
```

打开浏览器访问：[http://localhost:8001](http://localhost:8001)

## 🧪 评估与量化

| 维度 | 口径 | 说明 |
|------|------|------|
| 红旗召回 | `eval/cases.json` 用例集上的命中情况 | 规则层判定，**不依赖 LLM**；可用 `python eval/run_eval.py` 复跑 |
| 紧急误报 | 非红旗被误判为红旗 | 规则分级明确，尽量不过度告警 |
| 结构化输出 | 合法 JSON 落盘率 | 分层校验，非法即拒、绝不悄悄降级为空对象 |
| 会诊覆盖 | 四科并行同步评估 | 互不阻塞，墙钟 ≈ 最慢一科 |

### 知识库数据（启动必需）

`data/kb/` 下的三个 JSON（红症状库 / 用药禁忌库 / 症状→科室映射）是**业务知识库**，规则层在会诊前先做硬校验（不依赖 LLM），因此是**启动必需**、随仓库入库。缺失会让 `check_red_flags` 等直接抛错导致会诊中断。

### 评估与回归测试

- **离线回归**（无需 LLM）：`python -m pytest tests/ -v`，共 **27 项**，覆盖红旗召回 / 误报、联用检出、分层严格 JSON 的 GATE 判定、注入防护、限流器、**流式断开取消**，全部为纯逻辑测试。
- **端到端评估**（需 LLM）：`python eval/run_eval.py`，跑 `eval/cases.json` 用例集，量化红旗召回率、紧急误报率、科室命中率、降级样例数，结果落盘 `eval/results.json`（该文件为运行产物，已被 `.gitignore` 忽略）。

## 🛡️ 安全设计

- **密钥不入库**：`LLM_API_KEY` 仅存于项目根 `.env`（已被 `.gitignore` 忽略）
- **输入校验前置**：超长 / 非字符串请求直接 `400`，进入会诊前先扫描注入
- **高危指令隔离**：命中即替换为 `〔标记为数据〕`，分界符号隔离系统指令与用户输入
- **限流保护**：内存级速率限制（带定期清理与用户数上限），防恶意刷接口
- **审计留痕**：每次会诊记录红旗 / 各科结论 / 是否降级，全程可追溯
- **断开即止损**：SSE 客户端断开后立即置位取消信号，四科生成与后续仲裁尽快收尾，不再为已离开的用户消耗 LLM

> ⚠️ **免责声明**：本项目仅供就医参考，任何结论与建议**不能替代专业医疗诊断**。含红旗症状请务必及时就医。
